What is a skill?

A skill is a set of instructions that teaches Codex how to do one kind of job well, like planning or testing. It is a folder with a SKILL.md file in it. Five skills come with this starter, in .agents/skills/. Codex finds them when you open the project folder, in the app or in VS Code. You don't need to install anything.

Using one

  • Ask for it by name: “Use the plan-the-build skill.”
  • Or type $ in the Codex prompt and choose it from the list.
  • Codex may also choose one itself when your request matches.
  • Open the SKILL.md file to read what it will do. It is plain English. Your team can edit it.

The file AGENTS.md holds the house rules Codex reads before every task: plain HTML, no keys, stay in your own files. Add your own team notes at the bottom.

How to judge any tool in five minutes

  • Time to first result. Can you see something useful within 15 minutes?
  • Fits plain HTML. Does it need a build step, a framework or an install?
  • Accounts and keys. Does it need a sign-up or a key? A key cannot go in a public site.
  • Team cost. Will one person need to set it up for everyone, or does it just work?
  • What it teaches. Will it show you something new about building with AI?

Checkpoint 1 · Day 1 morning · 75 to 90 minutes

Plan

Show: a one-page PLAN.md, signed off by your team lead. It says who it is for, the one interaction that must work, your data, and who does what.

Default

plan-the-build skill In the starter

Codex asks your team questions one at a time: who the prototype is for, what it must do, which data it uses, and how you will split the work. It suggests two or three ways to build it, then writes PLAN.md. It does not write code.

Use the plan-the-build skill. We are a team of four and we have chosen the CGI growth story project.

Checkpoint 3 · End of Day 1 or Day 2 morning

Connected to real data

Show: your page reading real data. It can come from a public API that updates, or a dataset your team designs. Someone can change something on screen and see different results come back. The page shows where the data came from and handles loading, empty and error states.

Default

connect-data skill In the starter

Codex shows you one real response, agrees with you which fields the screen needs, and keeps the data code in its own file so teammates can work on the page at the same time. You design the loading, empty and error states together. Sample data stays as a fallback.

Use the connect-data skill. We want to use the ESCO skills API to suggest skill names as someone types.

Tools for looking at data

  • Hoppscotch: try an API request in your browser and see the response before you build anything. Nothing to install.
  • Your browser’s developer tools: the Network tab shows every request your page makes. The Console shows errors, such as a blocked request.
  • Context7: an MCP connection that gives Codex up-to-date documentation for libraries and APIs. It is optional and needs setup.
  • public-apis: a huge list of free APIs. Many are out of date or block browsers, so test before you commit.

Codex writes a short test script from your plan: three to five tasks written as real situations, not instructions, and checks your wording isn’t leading. While people test, it can check keyboard access and contrast. Afterwards it sorts your notes into the three lists.

All the way through

Four people, four AI assistants, one project

The hardest part of building with AI as a team isn’t the AI. It is four people changing the same files at once. These habits keep things working.

Default

team-handoff skill In the starter

Before you open a pull request, Codex checks your changes stay in your own slice. It brings in the latest main and writes a pull request description in plain language. It can also explain a teammate’s pull request to you, and take you through a merge conflict without silently picking a side.

Use the team-handoff skill. I’ve finished the skill search box and want to open a pull request.

Habits that prevent conflicts

  • Own a slice, own its files. Your PLAN.md says who owns which files. Ask before editing someone else’s.
  • Pull at the start of every block. Use Fetch origin, then Pull origin, before you ask Codex for anything.
  • Small pull requests, often. Aim for one each every hour or two. A 20-line change merges easily; a 400-line one doesn’t.
  • One integrator. One person merges pull requests and keeps main working. Everyone else asks them.
  • Don’t let the AI tidy up. Reformatting files you didn’t mean to change is the commonest cause of conflicts. AGENTS.md already tells Codex not to.

Make your own skill

If your team keeps typing the same instructions, turn them into a skill. Make a folder in .agents/skills/ with a SKILL.md file: a short name, a one-line description of when to use it, then the steps in plain English. Copy one of ours as a template. Codex also comes with a skill-creator skill that can draft one for you. It’s a good thing to show at playback.
